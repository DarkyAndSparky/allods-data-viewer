# FMOD Vorbis в FSB5 (кодек 15)

**Статус: проверено (2026-11-14).** Свой декодер (`crates/core/src/vorbis.rs`) сверен с выводом vgmstream
на 11 потоках банка `Voice_Kvator_Phrases_3_rus.fsb` (моно и стерео, 48 кГц, 28,6 млн отсчётов):
длины совпадают, расхождение не больше 2 единиц младшего бита (50% отсчётов совпадают точно;
разница в округлении и точности чисел с плавающей запятой). Ещё 62 потока из `SFX_Ambience`
и `Voice_Kvator_Phrases_2_2_rus.bsb` (в том числе 22 кГц и другие наборы кодбуков) декодируются
без ошибок, без тишины и без клиппинга; эталона для них нет. Четырёхканальная музыка
(`Music_Zone_*`) не проверялась.

## Как устроен поток

- Звуковые данные потока лежат с позиции `данные банка + смещение потока` (28 бит, в единицах по 16 байт
  в заголовке образца, биты 6..33); длина потока равна разнице смещений соседних потоков.
- Заголовки Vorbis (идентификация, комментарий, настройка) FMOD **не хранит**. Дополнительный блок
  типа 11 образца содержит CRC32 пакета настройки (`setup`), сам пакет берётся из таблицы
  известных настроек (кодбуки, полы, остатки, отображения, режимы).
- Размеры блоков фиксированные: короткий 256, длинный 2048. Частота и число каналов берутся из
  заголовка образца (блок типа 1 задаёт число каналов).
- Аудиопакеты идут подряд: `u16 длина`, затем пакет Vorbis без обрамления Ogg. Длина 0 или 0xFFFF
  означает конец. Число отсчётов ограничено значением из заголовка образца.

## Таблица настроек

Встроена вся таблица vgmstream: 161 настройка (лицензия ISC; в vgmstream они получены из
python-fsb5, который вытащил их из FMOD), сжатая zlib в `crates/core/data/vorbis_setups.bin.z`
(около 170 КБ). Файл делает `scripts/gen-vorbis-setups.py`; атрибуция в `NOTICE`. Тест разбирает все
161 настройку. Банк с неизвестным CRC даёт ошибку «not in the built-in list». Сквозная проверка
против vgmstream сделана только на пяти настройках из присланных банков; остальные 156 проходят
разбор, но не сравнивались с эталоном.

## Что реализовано

Спецификация Vorbis I: кодбуки (таблицы поиска 1 и 2), пол типа 1, остатки типов 0, 1 и 2,
отображение типа 0 с квадратурной связью каналов, окна, обратное MDCT через быстрое
преобразование Фурье. Пол типа 0 и нестандартные размеры блоков не поддерживаются.
Таблица `floor1_inverse_dB_table` строится как геометрическая прогрессия от 1,0649863e-7 до 1 (так,
как в libvorbis, с точностью до погрешности чисел с плавающей запятой).
