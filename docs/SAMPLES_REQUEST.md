# Какие образцы нужны (для дома)

Файл для владельца проекта. Образцы нужны, чтобы **проверить** форматы, а не угадывать. Всё, что вы пришлёте, остаётся у нас в рабочей переписке: **в репозиторий игровые данные не попадают** (это правило проекта, проверяется скриптом `check-repo.mjs`).

Если что-то уже присылали раньше, но в новой сессии я этого не вижу, пришлите снова: лучше дубль, чем догадка.

## Самый быстрый путь: один скрипт

1. Скопируйте `tools\collect-samples.ps1` из репозитория на свой компьютер.
2. Откройте PowerShell и выполните (путь замените на папку клиента игры):

```
powershell -ExecutionPolicy Bypass -File .\collect-samples.ps1 -GameDir "C:\Games\Allods"
```

3. На рабочем столе появится `adv-samples.zip`. Пришлите его мне.

Что делает скрипт: ничего не меняет в папке игры, ничего не отправляет по сети. Он читает все `.pak`, пишет список записей каждого пака, статистику по расширениям, первые 64 байта (hex) самых маленьких записей каждого расширения и копирует до двух самых маленьких файлов каждого расширения (не больше 300 КБ каждый). Размер архива обычно единицы мегабайт.

Скрипт я не мог запустить у себя (нет Windows и PowerShell). Если он выдаст ошибку, пришлите текст ошибки целиком, поправлю.

## Что нужно сверх скрипта (по приоритету)

| № | Что | Зачем | Как |
|---|---|---|---|
| 1 | Список папки с паками (имена и размеры) и номер версии клиента (RU / EU / другой сервер) | понять, какие паки и какие версии формата бывают | уже есть в `report.txt` из скрипта; номер версии напишите словами |
| 2 | **Два-три маленьких `.fsb` и/или `.bsb`** (до 1 МБ) | определить версию FSB и кодек; без этого звук не сделать | скрипт копирует маленькие; если их нет, найдите руками в паках звука |
| 3 | Один `.ogv` целиком (самый маленький) и название пака с видео | проверить кодеки (Theora, Vorbis) и способ воспроизведения | достать из `Video.pak` любым архиватором (пак это ZIP) |
| 4 | **Текстура `.bin` и запись о ней** в базе ресурсов | размеры, тип пикселей, порядок mip-уровней | пришлите сам `.bin` текстуры и файл базы ресурсов, в котором она описана; скажите, как текстура называется в игре |
| 5 | `pack.bin` и версия клиента, на которой он взят | база данных V1 или V2, x86 или x64 | файл целиком (он небольшой?). Если большой, пришлите первые 4 КБ и размер |
| 6 | Файлы `.xdb` (если есть) | описание полей баз | один-два небольших |
| 7 | Модель с текстурами и материалами: сама модель, её материал и текстура | **формат моделей полностью неизвестен**; нужен хотя бы один полный комплект | три файла одного предмета (например, простого оружия), укажите, как предмет называется в игре |
| 8 | Тексты `.loc` второго (64-битного) формата с нескольких версий игры | расшифровать раскладку v2 | у меня есть `Texts*.pak`; нужны ещё паки других версий. Если файл огромный, см. «Как отрезать начало файла» ниже |

Файлы 2–7 малы. Если мессенджер или чат не принимает файл, разрежьте архив или отрежьте начало (см. ниже).

## Как отрезать начало файла (первые 4096 байт)

```
$in  = [IO.File]::OpenRead("C:\путь\к\файлу.loc")
$buf = New-Object byte[] 4096
$n   = $in.Read($buf, 0, 4096); $in.Close()
[IO.File]::WriteAllBytes("$env:USERPROFILE\Desktop\head.bin", $buf[0..($n-1)])
```

Для `.pak` (это ZIP) достаточно любого архиватора; можно просто переименовать `X.pak` в `X.zip`.

## Ответы словами (на любом языке, коротко)

- Какая версия клиента, какой сервер (RU, EU, фан-сервер)?
- Есть ли в папке клиента что-то кроме `.pak` и `.exe`: отдельные `.loc`, `.fsb`, `.bsb`, `.ogv`?
- Какой формат вы хотите видеть первым результатом: текст (`.loc` в CSV), текстуры (PNG), звук (WAV/MP3)?

## Что я сделаю, когда получу

| Образец | Результат |
|---|---|
| `.fsb` / `.bsb` | описание в `docs/formats/media.md` со статусом `verified`, затем веха M3 |
| `.ogv` | уточнение для вехи M4 (воспроизведение, перекодирование) |
| текстура + база | веха M2 (`.bin` → PNG/DDS) |
| `pack.bin` | веха M6 (базы в JSON/XML) |
| модель, материал, текстура | веха M7–M8 (glTF, просмотр в Three.js) |
| `.loc` v2 | завершение M1 (оба формата `.loc`) |

Присланное **не** хранится в репозитории, не публикуется и используется только для проверки разбора форматов.
