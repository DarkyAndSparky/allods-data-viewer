# Безопасность и качество

Модель угроз для программы, читающей чужие файлы, лимиты, тесты, бюджеты скорости и CI.

Что уже есть в репозитории: `SECURITY.md`, `deny.toml`, `.github/workflows/security.yml`, `scripts/check-repo.mjs`, `scripts/guard.mjs`, раздел «Parser rules» в `docs/engineering/WORKFLOW.md`. Числа и бюджеты ниже — **предложение**, измерений на реальных данных пока нет.

## 1. Модель угроз

Программа офлайн, без сети, без аккаунтов. Главный риск: **недоверенные файлы**. Вы открываете паки с фан-серверов, моды и чужие сборки, то есть файл может быть создан злоумышленником.

| № | Угроза | Вектор | Последствие | Противодействие |
| --- | --- | --- | --- | --- |
| T-01 | Запись за пределы папки при распаковке (zip-slip) | имя записи `../../x`, абсолютный путь, `C:\...`, имя с `\` | перезапись файлов пользователя | `VPath` отвергает недопустимые пути при открытии; перед записью проверяется, что итоговый путь внутри папки вывода; символьные ссылки не следуются |
| T-02 | Архив-бомба | запись 1 МБ распаковывается в десятки ГБ; двойной слой zlib | забитый диск или память | лимиты вывода и коэффициента сжатия; общий лимит на одну операцию экспорта; только потоковое чтение |
| T-03 | Неправдоподобные длины и смещения в форматах (`count`, `str_size`, `pos`) | повреждённый `.loc`, база, текстура | паника, чтение за массивом, гигантское выделение памяти | проверка диапазонов, checked-арифметика, запрет `unsafe`, ошибки значением, fuzz |
| T-04 | Взрыв числа элементов (`count = 4 млрд`) | заголовок с гигантским числом | нехватка памяти | никакого `with_capacity` от непроверенного числа; `count * размер_записи` должно умещаться в файл |
| T-05 | Внедрение разметки в интерфейс (XSS) | текст из `.loc` с `<script>` или `<img onerror>` | выполнение кода в окне приложения, доступ к командам Tauri | вывод только через `textContent`/`escapeHtml`; строгий CSP; минимальные capabilities |
| T-06 | Злонамеренный путь в команде IPC | интерфейс просит прочитать произвольный файл | чтение чужих файлов | IPC принимает идентификатор источника, а не путь; пути только из диалога выбора файла |
| T-07 | Перезапись клиента игры | `adv pack` в папку игры | поломка клиента, нарушение правил игры | только новые файлы; отказ писать в папку с клиентом без явного флага |
| T-08 | Внешние программы (`lame`, `ffmpeg`) | подмена бинарника на пути | запуск чужого кода | путь задаётся явно в настройках; аргументы передаются массивом, без оболочки; никаких имён файлов из данных в командной строке |
| T-09 | Подмена зависимости (supply chain) | вредоносный пакет в crates.io / npm | выполнение кода на машине разработчика | `Cargo.lock` и `package-lock.json` в репозитории, `cargo deny`, `cargo audit`, `npm audit`, Dependabot, мало прямых зависимостей |
| T-10 | Утечка игровых данных в репозиторий | случайный `git add` образца | нарушение прав и лицензии | `check-repo.mjs` в CI, `.gitignore`, папка `samples/` запрещена |
| T-11 | Подмена релиза | поддельный бинарник на GitHub | малварь под видом программы | сборка только в CI, контрольные суммы SHA-256, SBOM, аттестация сборки (веха M11) |

Вне модели: компрометация машины администратора, вредоносные паки вида «взлом аккаунта игры» (мы не трогаем сеть и клиент).

## 2. Лимиты (предложение, числа обсудить)

Лимиты живут в `crates/core/src/limits.rs` как константы с возможностью увеличить через настройку `--limits`. Нарушение даёт ошибку `Limit`, а не панику.

| Лимит | Значение по умолчанию | Основание |
| --- | --- | --- |
| Записей в одном `.pak` | 10 000 000 | с запасом; известные паки гораздо меньше |
| Длина пути записи | 1024 байта | даёт запас на Windows (длинные пути требуют префикса) |
| Распакованный размер одной записи после слоя ZIP | 2 ГиБ | без ZIP64 большего не бывает |
| Размер после второго слоя zlib | 1 ГиБ | самый большой наш `.loc` занимает 71 577 688 байт |
| Коэффициент сжатия для записей крупнее 1 МиБ | 2000 : 1 | данные типа «много нулей» дают до тысячи : 1; нужно проверить на образцах |
| Глубина вложенных слоёв zlib | 2 | видим максимум один дополнительный слой |
| Элементов в `.loc` | 5 000 000 | максимум в образцах — 566 294 |
| Длина ключа `.loc` | 4096 байт | ключи — пути вида `A/B/C.txt` |
| Длина одного текста `.loc` | 16 МиБ | для одной записи, с запасом |
| Размер текстуры | 16 384 × 16 384 | больше в игре не ожидается; проверить |
| Число mip-уровней | 16 | log2 от 16 384 равен 14 |
| Число потоков в звуковом банке | 65 536 | будет пересмотрено по образцу |
| Число параллельных потоков экспорта | число ядер | `--jobs N` меняет |
| Размер потока чтения буфера | 64 КиБ | баланс скорости и памяти |

## 3. Безопасное извлечение файлов

Порядок действий `adv extract` для каждой записи (предложение):

1. Проверить путь: без `..`, без начального `/` и `\`, без буквы диска `X:`, без байта `0`, не пустой.
2. На Windows заменить запрещённые символы (`< > : " | ? *`) и зарезервированные имена (`CON`, `NUL`, `COM1` и т. д.), записать замену в отчёт.
3. Собрать итоговый путь = папка вывода + путь записи; убедиться, что он находится внутри папки вывода после нормализации.
4. Если файл уже есть: не перезаписывать без `--overwrite`; на регистронезависимой системе случай «два пути различаются регистром» считается коллизией, в отчёт.
5. Записать во временный файл рядом и переименовать после проверки CRC32.
6. Не создавать символьные ссылки и не следовать им.

## 4. Приложение Tauri (веха M5): предложение

- **CSP** в `tauri.conf.json`: `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data: blob:; media-src 'self' blob:; font-src 'self'; connect-src ipc: http://ipc.localhost`. Без `unsafe-inline` и `unsafe-eval`. Точный текст сверить с документацией Tauri 2.12 на вехе M5 (сейчас не проверено).
- **Capabilities:** только нужные команды наших плагинов и диалог выбора файла; никакого доступа к `fs` из интерфейса, никакого `shell`, `http`.
- **Сеть:** окно не загружает внешние адреса; навигация на внешние ссылки запрещена (ссылка на GitHub в «О проекте» открывается в системном браузере по списку разрешённых).
- **Данные в интерфейсе:** ключи и тексты из игры показываются только через `textContent`; в `about.ts` уже есть `escapeHtml` с тестом.
- **Видео:** воспроизводится через `blob:`-адрес из данных, которые дало ядро; вебвью должен уметь Theora (на Linux зависит от системных пакетов, не проверено).

## 5. Уровни тестов

| Уровень | Что | Где запускается | Статус |
| --- | --- | --- | --- |
| 1. Синтетические | маленькие входы, собранные в коде теста (валидные, обрезанные, повреждённые, гигантские заголовки) | локально и CI, `cargo test` | есть только smoke на M0 |
| 2. Свойства | `proptest`: «любой байтовый массив не роняет разбор»; «запись потом чтение даёт исходное» | CI | не начато |
| 3. Fuzz | `cargo fuzz` (0.13.2, 2026-06-09) для каждого читателя по мере появления | ночной запуск, без обязательного результата на ветку | не начато |
| 4. Снимки вывода | `insta` (1.49.0): вывод `adv` на синтетических входах и JSON-схемы | CI | не начато |
| 5. Внешние образцы | реальные файлы из `ADV_SAMPLES`: «каждый элемент разобран, остатка нет» | только у вас (файлы не в репозитории) | план |
| 6. Сравнение с эталоном | результат сравнивается с выводом другого инструмента (например, MIT-проект для баз и текстур) на тех же образцах | только у вас | план |
| 7. Интерфейс | `vitest`: i18n, `escapeHtml`, форматирование; `playwright` (1.65.0) — экраны с подменой IPC | CI | `vitest`: 11 тестов (проверено); `playwright`: не начато |
| 8. Скрипты | `node --test`: охранник, `check-repo` | CI | 41 тест (проверено) |

Правило: новый читатель не принимается без уровней 1 и 2; перевод формата в `verified` требует уровня 5.

## 6. Бюджеты скорости и памяти (предложение, не измерено)

| Операция | Цель |
| --- | --- |
| Открыть папку клиента и показать список файлов | до 2 с на обычном SSD (читается только центральный каталог каждого пака) |
| Поиск по именам файлов | меньше 100 мс на миллионе записей |
| Разбор `.loc` на 300 000 элементов | меньше 1 с, без пика памяти выше двукратного размера файла |
| Превью текстуры | меньше 200 мс для 2048 × 2048 |
| Пакетный экспорт | скорость близка к скорости диска и CPU; память не растёт с числом файлов |
| Отклик интерфейса при прокрутке списка | 60 кадров в секунду на миллионе записей (виртуализация) |

Для проверки нужны `criterion` (0.8.2, 2026-02-04) и реальные паки: без них эти числа не проверяемы.

## 8. Что не решено

- Какой у нас порог «подозрительного» коэффициента сжатия: 2000 : 1 — угаданное число, нужны реальные паки.
- Нужно ли вести журнал операций в приложении (кто, что, куда извлёк); заимствовано из аудита ядра, для однопользовательской программы скорее ненужен (предложение: без журнала, только `manifest.json` для `adv verify`).
- Подпись бинарников Windows: сертификат платный; без него SmartScreen будет предупреждать при запуске.
