## 2. Целевая структура ядра (предложение)

Каждый модуль закрывает один этап роадмапа. Пустых заготовок заранее не создаём: папка появляется вместе с первым тестом.

```
crates/core/src/
├── error.rs          Error, ErrorKind, контекст (файл, смещение)           M0 ✅
├── limits.rs         предельные размеры и глубина вложенности              M1
├── progress.rs       Progress: отчёт о ходе и отмена                       M1
├── detect.rs         определение формата по заголовку и имени              M1
├── vfs/              VPath, Entry, Vfs: несколько паков как одна ФС        M1
├── archive/          pak.rs (чтение ZIP), pakwriter.rs (запись)            M1, M10
├── codec/            zlib.rs, crc.rs, dxt.rs, wav.rs                       M1–M3
├── formats/
│   ├── loc/          v1.rs (32 бита), v2.rs (64 бита)                      M1
│   ├── texture.rs    .bin текстуры                                         M2
│   ├── audio/        bsb.rs, fsb.rs                                        M3
│   ├── video.rs      .ogv: сведения и извлечение                           M4
│   ├── db/           базы .bin                                             M6
│   └── model/        модели и материалы                                    M7–M8
└── export/           csv.rs, json.rs, png.rs, gltf.rs                      M1–M7
```

Когда появится приложение (M5), добавится пакет `crates/app` с оболочкой Tauri. Он только вызывает ядро и не содержит разбора форматов.

## 3. Ключевые типы (предложение)

Это эскиз для обсуждения, не готовый код (не проверен компиляцией, упущение G-17). Имена и поля можно менять, пока нет первой реализации.

```rust
/// Путь внутри виртуальной файловой системы: UTF-8, разделитель '/', без '..'.
pub struct VPath(String);

pub enum Method { Stored, Deflate }

pub struct Entry {
    pub path: VPath,
    pub size: u64,          // размер после слоя ZIP
    pub packed_size: u64,
    pub crc32: u32,
    pub method: Method,
    pub pack: PackId,       // из какого .pak
}

pub struct Vfs { /* список паков и индекс путей */ }

impl Vfs {
    pub fn open(path: &Path) -> Result<Vfs>;                  // папка Packs или один .pak
    pub fn entries(&self) -> impl Iterator<Item = &Entry>;
    pub fn read(&self, p: &VPath, layer: Layer) -> Result<Box<dyn Read + '_>>;
}

/// Снимать ли второй слой zlib.
pub enum Layer { Raw, Decoded }

pub enum Kind { Pak, LocV1, LocV2, TextureBin, DbBin, Bsb, Fsb, Ogv, Ttf, Unknown }
pub fn detect(head: &[u8], name: &str) -> Kind;

pub struct LocItem { pub key: String, pub text: String }

pub trait Progress: Sync {
    fn report(&self, done: u64, total: u64);
    fn cancelled(&self) -> bool;
}
```

## 4. Ошибки

Ошибки возвращаются значением. Каждая несёт контекст: какой файл, какое смещение, что ожидалось. Паника на любых входных данных считается багом.

| Вид | Когда | Код выхода CLI |
| --- | --- | --- |
| `Io` | не удалось прочитать или записать файл | 1 |
| `Format` | файл повреждён или не соответствует описанию | 1 |
| `Unsupported` | формат или версия известны, но не поддерживаются (например, неизвестная версия базы) | 1 |
| `Crc` | контрольная сумма записи не совпала | 1 |
| `Limit` | превышен предельный размер или вложенность | 1 |
| `Cancelled` | операцию отменил пользователь | 130 |
| частичный успех | часть элементов обработана, часть пропущена | 2 |

## 5. Правила виртуальной файловой системы

- **Пути.** Хранятся как в архиве. Абсолютные пути и `..` отвергаются при открытии (защита от записи за пределы папки при распаковке).
- **Регистр.** Клиент работает в Windows, значит имена, скорее всего, не различают регистр. Предложение: сравнивать без учёта регистра по ASCII, а при распаковке на Linux сообщать о коллизиях. Нужно проверить на реальных паках.
- **Несколько паков.** Если один путь есть в нескольких паках, предложение: побеждает пак, который идёт позже по имени. Правило неподтверждено, нужен список паков и проверка на повторы (открытый вопрос Q-03).
- **Слой zlib.** Определяется по первым двум байтам (`0x78` и одно из `0x01`, `0x5E`, `0x9C`, `0xDA`), по умолчанию снимается; режим `--raw` отдаёт данные как есть. Запись, которая начинается как zlib, но не распаковывается, считается обычными данными.
- **Размеры.** Самый большой из наших образцов `.loc` в распакованном виде занимает 71 577 688 байт, новый формат около 45 МБ. Поэтому `.loc` можно читать в память целиком, но с лимитом, а звук, видео и большие пакеты только потоком.

## 7. Прочие правила

- **Параллелизм.** Пакетный экспорт идёт через `rayon`; каждый поток открывает свой дескриптор архива, читатели не делят изменяемое состояние.
- **Отмена и прогресс.** Долгие операции принимают `Progress` и проверяют отмену не реже, чем раз в 100 мс.
- **Версионирование.** Ядро следует SemVer. JSON-вывод CLI содержит поле `schema` с номером; поля не удаляются в рамках одного номера.
- **Windows.** Длинные пути обрабатываются через префикс `\\?\`, недопустимые в Windows имена файлов при распаковке на Windows заменяются с записью в отчёт.
- **Без `unsafe`.** В рабочей области стоит `unsafe_code = "forbid"`, исключений не планируем.
